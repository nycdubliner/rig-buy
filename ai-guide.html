1. Local OS & AMD ROCm Driver Setup

While Windows has improved, Ubuntu 22.04 LTS or 24.04 LTS is mandatory for a stable, multi-GPU AMD setup. Linux memory allocation and tensor splitting algorithms are vastly superior here.

Installation Steps

After installing Ubuntu, you must install the proprietary AMD drivers and the ROCm (Radeon Open Compute) stack. Your 7800 XTs use the RDNA3 architecture (gfx1101), which is officially supported by modern ROCm.

# 1. Download the AMD installer
wget https://repo.radeon.com/amdgpu-install/6.1.2/ubuntu/jammy/amdgpu-install_6.1.20102-1_all.deb
sudo apt-get install ./amdgpu-install_6.1.20102-1_all.deb

# 2. Install the usecase for ROCm
sudo amdgpu-install --usecase=rocm
CRITICAL: Permissions
If you do not add your user to the video and render groups, Ollama will quietly fail to find your GPUs and will fallback to your CPU, running incredibly slowly. 
sudo usermod -a -G video $USER
sudo usermod -a -G render $USER
# You MUST reboot after this command

Verification

After rebooting, run the ROCm System Management Interface to verify both 7800 XTs are recognized:

rocm-smi

2. The Inference Stack (Ollama)

The "Engine" loads the massive matrix of numbers into your VRAM and calculates the next token. Ollama (backed by llama.cpp) is the easiest and most robust tool for this.

Why Ollama? (Tensor Splitting)

When you load a 24GB model, it will not fit on a single 16GB 7800 XT. Ollama automatically handles Tensor Splitting, slicing the model in half across the PCIe bus, utilizing both GPUs seamlessly.

Installation

curl -fsSL https://ollama.com/install.sh | sh

Once installed, Ollama runs as a background systemd service. It automatically exposes an OpenAI-compatible REST API on http://localhost:11434/v1.

3. Model Families & Quantization

A standard uncompressed (FP16) 32 Billion parameter model requires ~64GB of VRAM. To fit it into your 32GB budget, we use Quantization (compressing the model to 4-bit, 5-bit, or 6-bit precision, typically using the GGUF format).

A 32B model quantized to 6-bit (Q6_K) shrinks from 64GB down to ~24GB. This fits beautifully across your dual 7800 XTs, leaving 8GB of VRAM left over for your "Context Window" (the code files you send the agent).

The Heavyweights

  • Qwen 2.5 Coder 32B: The undisputed king of open-weight coding models. Exceptionally strong in typed languages like Golang and Rust. This is your primary daily driver for agentic coding. Run via: ollama run qwen2.5-coder:32b
  • Llama 3.1 8B: Blazing fast. Excellent for quick bash scripting, formatting text, or "router" agents. Uses < 6GB of VRAM.
  • Gemma 2 27B: Google's dense powerhouse. Incredible general reasoning and logic skills, fits comfortably in your VRAM limit.
The 70B Trap: Even heavily quantized, a 70B model requires ~40GB of VRAM. Your system will "spill" the remaining 8GB into your slow DDR4 system RAM, causing generation speed to drop off a cliff (e.g., from 25 tokens/sec to 3 tokens/sec). Stick to ~32B models.

4. Benchmarks & Local Evaluation

Do not rely on Twitter hype. Use specific, empirical benchmarks to evaluate new models.

  • The Aider LLM Leaderboard: Tests how well a model can read an existing, complex codebase, understand it, and surgically edit specific lines without breaking the file. The most important metric for agentic coding.
  • SWE-bench: Tests a model's ability to autonomously navigate a massive repository, find a bug based on a GitHub issue, and generate a patch.
  • LMSYS Chatbot Arena: A blind A/B testing leaderboard based on Elo ratings. Good for assessing "vibes" and instruction-following.

Local Verification

When you download a new model, test its Context Degradation (the "Needle in a Haystack" test). Dump 10 massive Golang files into the prompt and ask a specific question about a buried variable. If it hallucinates, the model's context window cannot handle agentic workloads.

5. Hooking up Agentic Workloads

Agentic tools (like CLAW, Aider, and Cline) are typically hardcoded to look for the OpenAI API. You "trick" them into talking to your local GPUs by overriding two environment variables:

export OPENAI_API_BASE="http://localhost:11434/v1"
export OPENAI_API_KEY="dummy-key-ollama"

The Tools

  • CLAW / Gemini CLI: Terminal-based, multi-step execution. Excellent for massive refactoring loops and running integration tests autonomously.
  • Aider: A terminal pair programmer that tracks your git repository and surgically edits your files.
  • Cline / Claude Dev: A VSCode extension that lives in your sidebar, reads open files, and proposes diffs visually.
Context Window Blowout: Every 8,000 tokens of context requires roughly 1GB of VRAM to hold in memory. If your agent tries to send 100,000 tokens of context alongside a 24GB model, your 32GB VRAM will overflow. Solution: Use .aiderignore or .clineignore files to hide massive directories (like node_modules) from the agents.
