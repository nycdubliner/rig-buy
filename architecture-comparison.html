Zero-Copy AI Supremacy

When running large Local LLMs, the massive model weights sit in the 64GB+ unified RAM pool. The iGPU has direct, zero-copy access to this memory. It doesn't need to copy the 30GB model over a PCIe bus to its own VRAM because it already owns the system RAM. This allows APUs to run massive 32B+ models incredibly efficiently.

The Gaming King

In gaming, the massive graphical textures are pre-loaded into GPU 1's dedicated GDDR6 VRAM. The GPU core communicates with this VRAM at an insane ~624 GB/s. The PCIe bus is barely stressed, only receiving geometry and draw calls from the CPU. Because there is no bandwidth sharing with the CPU, framerates are blistering compared to an APU.

The Synthesis: Why Build Dual-GPU?

If APUs (like Mac Studio or Strix Halo) are so good at AI, why build a Dual-GPU rig? Because of the VRAM bandwidth multiplier.

An APU might have 64GB of RAM, but its bandwidth is limited to ~120 GB/s. A single RX 7800 XT has 624 GB/s of bandwidth. When you run a 32B model across two 7800 XTs, you suffer a slight latency penalty when the layers split across the PCIe bus (as shown in the AI animation above), but the actual computation happening inside the GDDR6 VRAM is happening at over 1,200 GB/s combined.

Result? The APU can hold the model, but generates tokens slowly (e.g., 5-8 tokens/sec). The Dual-GPU rig has to split the model, but computes so violently fast that it overcomes the PCIe penalty and outputs at 25+ tokens/sec, while also remaining a world-class gaming PC.
