Key finding: MTP=4 speculative decoding provides a 2.2× throughput improvement over no-MTP (190 vs 85 tok/s). The draft model (google/gemma-4-31B-it-assistant) is only ~2B params and stays in BF16. vLLM correctly clears quant_config for the assistant model when the target is quantized but the assistant path differs (PR #37667).
Do NOT use: --kv-cache-dtype fp8 — this requires CDNA3 (MI300) and causes silent failures on RDNA3 (7900 XTX). It was the root cause of earlier hotspot temps (GPU 1 reaching 77°C edge / ~100°C junction at 226W). Removing it dropped junction temps to 46–57°C under load.

Root cause: vk::DeviceLost on queue submit when allocating >~8 GB VRAM through RADV. MTP Speculative Decoding Scaling

Multi-Token Prediction (MTP) is Gemma 4's native speculative decoding. A small draft model (~2B params) predicts multiple future tokens; the target model verifies them in parallel. Each accepted token saves one full forward pass.

MTP TokensTotal tok/sSpeedupTPOT (ms)
0 (no MTP)851.0×58
11291.5×37
21621.9×29
41902.2×24
Diminishing returns: MTP=1→4 is a 47% improvement over MTP=1 alone. The draft model's predictions diverge as the lookahead grows, so acceptance rate drops. MTP=4 is the sweet spot on this hardware.

Thermal Analysis

FP8 was the hotspot culprit: --kv-cache-dtype fp8 requires CDNA3 (MI300). On RDNA3 (7900 XTX), vLLM falls back to a software emulation path that burns extra power with zero throughput gain. GPU 1 at 226W with FP8 vs ~150W without it explains the 20°C edge temperature difference. No undervolting needed — just remove the broken flag.

Deployment Lessons

✅ What Works

/v1/chat/completionsOpenAI-compatible chat endpoint — fully working with Gemma 4 chat template
/v1/messages?beta=trueAnthropic API (Claude-compatible) — requires --enable-auto-tool-choice
AWQ 4-bitOnly stable quantization on ROCm/RDNA3. GPTQ is unstable, FP8 is MI300-only.
MTP speculative decoding2.2× speedup with zero quality loss. Draft model loads automatically.
TP=2Tensor parallelism works on PCIe Gen 4 x8 — unlike the 7800 XT setup where PP was preferred

❌ What Doesn't Work

/v1/completionsProduces repetitive garbage — vLLM doesn't apply chat template for this endpoint with Gemma 4
--kv-cache-dtype fp8MI300-only. Causes hotspot temps and zero benefit on 7900 XTX.
--enable-chunked-prefillKV cache OOM at 160K max-model-len on 24GB cards. Needs lower max-model-len (~131K).
llama.cpp Vulkan GPU offload (31B+)RADV DeviceLost crash on large VRAM allocations. Use ROCm/HIP backend.
GPTQ quantizationUnstable on ROCm — garbled output reported consistently.

🔧 vLLM Nightly Regressions

The vllm bench serve tool's decode_throughput and prefill_pressure scenarios fail with connection errors due to a timing bug in the benchmark client. The server itself is fine — the benchmark runner tries to connect before the server finishes transitioning between workload phases. This is a vllm bench bug, not a model or server issue. All interactive scenarios completed successfully.
